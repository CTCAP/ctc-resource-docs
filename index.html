Governance

The system serves those who built it

Affiliates retain ownership. Files stay in affiliate-controlled Drive. The system holds metadata and links only.
Permission set at submission. Nothing becomes more visible without explicit approval at the point of submission.
Withdrawal is always possible. Affiliates can request removal of any resource at any time through their stream coordinator.
Participation is invited, not required. The network grows through trust, not mandate.
Each stream governs itself. Stream coordinators hold full triage and approval authority within their stream.

CalculationWhat it reveals
Degree centralityHow many connections does this node carry? High-degree cities are hubs of activity. Degree 1–2 nodes are isolated — often the most strategically important finding.
BetweennessWhich nodes sit on the most paths between others? A theme with high betweenness bridges separate clusters — often the most theologically interesting finding. Gospel DNA and Leadership Development consistently score high here.
Clustering coefficientHow tightly connected are a node's neighbours? High clustering = tight community of related resources. Low clustering on a well-connected node = genuine broker between worlds.
EigenvectorNot just how many connections, but how important are they? A resource connected to many high-value resources scores higher than one connected to many peripheral ones. This is what PageRank is built on.
Metadata Insight Layer — Claude API
Gap nodes are surfaced explicitly. The insight layer reads approved metadata rows — never file content — and generates strategic briefs: gap analysis, translation priorities, bridge resource identification, cluster narratives.

The layer calls the Claude API via Apps Script UrlFetchApp. No file content is ever sent — only approved metadata fields. A single "Generate network insights" button on the admin dashboard sends the current Sheet data as a structured prompt and returns an interpretive brief that renders next to the graph, entirely within the Google ecosystem.

Human-Centred Design Process

Designed before it is built

The category vocabulary, permission logic, and workflow emerge from the people who will use the system. Timeline is process-driven, not date-driven.

01
Team Alignment
Individual conversations with each stream team lead before any group session. The goal is whether the direction is right — not a briefing.
02
Stream Working Sessions
One 60-minute session per stream: what do you collect, who owns it, what do you call it? Output: draft category list, coordinator nomination, affiliate contacts.
03
Affiliate Outreach
Through existing stream coordinator relationships. The message: we are designing this together before anything is built.
04
Participatory Survey
Affiliates vote on candidate category tags, permission options, and language fields.
05
Schema Consolidation
Controlled vocabulary agreed across all three streams. Build decision follows.
